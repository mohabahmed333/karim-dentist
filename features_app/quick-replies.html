Quick replies

Saved WhatsApp messages staff insert by typing /key in a chat — filled in with the patient's details, sent with a file or the clinic's location, and now with up to three reply buttons. What a patient taps back is shown clearly, not lost.

Built, on local mainCommitted directly to main — no feature branch. Nothing pushed to GitHub yet, so Vercel has not deployed any of this.
Live database already updatedEvery migration these three features need is applied to the production Supabase project.
No Meta approval neededEverything here sends within the 24-hour reply window, as an ordinary session message — not a template.
Nothing switched off by defaultUnlike the auto-responder, quick replies are a staff tool: whatever is saved and active is usable immediately.

What every reply shares

A saved reply is text, plus anything optional it carries — fill-in fields, one attachment, up to three buttons. Choosing it from the / menu fills everything in; nothing about a reply is decided at send time that staff cannot already see in the message box.

Never sent half-filled
A field with no value stays as {{field}} in the text, and Send is disabled until it is replaced
Per conversation
Switching to another chat and back keeps the draft, its attachment and its buttons together, exactly as left
Sent once
A second click while a file is still downloading is ignored — the message never goes out twice
English and Arabic
Title, body and button labels each have an Arabic version; fields and buttons fill in the language of the text actually inserted

Why it may not fill in 3 conditions
  • The chat is linked to a patient{{name}} and {{next_appointment}} need a phone match against a patient or a reservation.
  • A visit is actually upcomingNo booked, non-cancelled future visit means {{next_appointment}} and {{appointment_service}} stay unfilled.
  • Site settings and clinic hours are filled inMissing ones fall back to defaults rather than staying blank, so these rarely block sending.

Attachments

Live

A reply can carry one image, one PDF, or the clinic's location pin, sent as its own message.

WhenA reply with an attachment is chosen and sent.

  • Images (JPEG/PNG) and PDFs, uploaded on the management page — up to 4 MB.
  • The reply text becomes the file's caption, unless it is over 1,024 characters, in which case the text goes first, then the file with no caption.
  • A location reply sends the text first, then the clinic's pin.
  • Picking a different reply replaces the attachment; clearing the message box removes it.

Manage on one page

Live

Every reply is created, edited and grouped in one place, and the busiest ones float to the top of the / menu.

WhenA reply is used — the menu re-sorts the next time it opens.

  • The / menu lists replies by how often each is used, then by the order set on the page; it also matches on category, so /price finds anything tagged “Pricing”.
  • A reply switched off never appears in the menu, however often it was used before.
  • Each reply shows an attachment icon or a buttons icon in the list, so staff can tell what it sends without opening it.

For staffQuick replies — add, edit, group by category and preview a reply filled with a sample patient before saving.

Save a sent message as a reply

Live

A good answer staff just typed can be saved as a quick reply without retyping it.

WhenStaff hover a plain text message they sent and choose the bookmark icon.

  • Only plain sent text — not media, voice notes or an already-interactive message.
  • An Arabic message is saved under the Arabic body too, so it works straight away.
  • A slash key already in use is refused with the exact reason, not a generic error.

Reply buttons

Up to three reply buttons, saved on the reply and inserted with it.

Saved buttons

Live

A reply can carry up to three reply buttons, each with an English label and an optional Arabic one.

WhenStaff add buttons to a reply on the management page; inserting the reply inserts the buttons with it.

  • Twenty characters per label — WhatsApp's own limit — with duplicate labels refused before saving, not after sending.
  • A label cannot contain a fill-in field: twenty characters leaves no room for one.
  • Labels follow the language of the inserted text, falling back to English when the Arabic label is blank.
  • Inserting a reply replaces whatever buttons were there; a reply with none removes buttons an earlier reply added, but never buttons staff built by hand.

Why sending a button message may fail 3 conditions

Checked before the message reaches WhatsApp, and reported back with the exact reason.

  • At least one buttonAn interactive send with no buttons is refused.
  • Text within 1,024 charactersWhatsApp's limit for a message that also carries buttons.
  • No two buttons with the same labelCase and spacing ignored — WhatsApp rejects the whole message, not just the duplicate.

When a patient taps

What happens to a reply button or list-item tap once it reaches the inbox.

Shown as a chip, not text

Live

A tapped button or list item is captured — its id, its label, and which kind it was — and shown as a small chip, distinct from something the patient typed.

WhenA patient taps a reply button or a list row on any message the clinic sent.

  • Kept in the message's existing flow field — no database change was needed to add this.
  • The tap still quotes the message it answered, the same as any WhatsApp reply.
  • A tap with no title or id — not something WhatsApp normally sends — falls back to plain text rather than showing an empty chip.

For staffNothing to do — the chip renders on its own wherever the tap appears in a chat.

Known gaps

  • Tapping a button does nothing on its own — no booking, no confirmation, no automatic action. It is captured and shown, not acted on.
  • A template quick-reply button (outside the 24-hour window) is not read — no approved WhatsApp template has buttons yet.
  • A message sent with buttons cannot also carry an image or PDF as its header — the file goes as its own message first instead.
  • If one message in a multi-part send fails (the file, say), the later parts still go out — nothing currently stops the sequence partway.
  • A tap message stored before this shipped has no chip and still shows as plain text; nothing was backfilled.
